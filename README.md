# daylog

Журнал рабочего дня по снимкам экрана. Раз в минуту `daylog.py` снимает все мониторы, LLM (через `claude -p`) описывает, чем ты был занят, а в конце дня склеивает минуты в таймлайн. Приложение в `app/` показывает дни в окне и включает запись кнопкой.

Только macOS. Нужны `python3` (только стандартная библиотека) и Claude Code CLI (`claude`) для вызовов LLM. Для сборки приложения — Rust (cargo), Node.js и pnpm.

## Командная строка

```sh
python3 daylog.py run                 # сборщик: кадр раз в минуту, описание пачками по 5 минут
python3 daylog.py report 2026-11-16   # таймлайн дня в report.md и report.json (по умолчанию — сегодня)
python3 daylog.py summarize           # описать накопленные кадры (сборщик зовёт сам)
python3 daylog.py classify 2026-11-16 # разметить категориями описанные минуты без категории
python3 daylog.py pause 2026-11-16 14:22 14:30 "поговорил с Игорем"   # причина паузы за этот отрезок дня
```

`run` держит блокировку на `collector.lock` в каталоге данных: на один каталог работает не больше одного сборщика. Коды выхода `run`: 2 — сборщик уже запущен (в сообщении его PID), 3 — нет разрешения на запись экрана.

`report` склеивает минуты в крупные блоки занятий длиной от 10 минут до 2 часов. Граница блока — смена основного занятия. Отвлечения короче 10 минут (личная переписка, YouTube, короткая пауза) не становятся отдельными интервалами, а упоминаются в описании блока: «между делом минуты три переписывался в Telegram». Категория блока — преобладающая среди его минут, описание — 1–3 предложения. Пропуск в записях от 10 минут — отдельный интервал «не за компьютером». Занятие дольше 2 часов делится на несколько блоков. Точное время по категориям — в итогах дня в приложении: они считаются по минутам, а не по отчёту.

`report` перед сборкой дописывает неописанные минуты и размечает минуты без категории, поэтому для дня с большим хвостом это долго и стоит денег, как и сам вызов LLM.

`pause` дописывает в `pauses.jsonl` дня причину паузы: зачем отходил от компьютера. Отрезок задаётся началом и концом, конец — минута после последней минуты паузы. Причина относится к паузе, с которой отрезок пересекается. Чтобы исправить причину, запиши новую для того же отрезка: действует последняя. День должен уже быть в каталоге данных, LLM команда не вызывает.

## Категории

Каждая описанная минута получает категорию — тем же вызовом LLM, что и описание:

- `work` — рабочее: код, ревью, задачи и тикеты, рабочие чаты и созвоны, рабочие документы;
- `nonwork` — нерабочее: личные переписки, развлечения, новости, покупки;
- `idle` — ничего не делал: пауза (см. ниже) или явный простой на снимке: экран блокировки, заставка, пустой рабочий стол. Если экран просто не меняется (читаешь документ), это не простой; при сомнении минута считается занятием.

Созвон — рабочее, если на экране не видно явно личного звонка (Telegram, FaceTime с личным контактом).

Что для тебя работа, можно описать своими словами в `$DAYLOG_DIR/work.md` (например, «daylog — личный проект, не работа»). Файл необязательный и читается при каждом описании, правка действует на следующие минуты.

Минуты, описанные до появления категорий, размечает `daylog.py classify <день>`: один текстовый вызов LLM на день, без снимков. Приложение делает это само, когда открываешь такой день.

## Паузы и созвоны

Пока Mac не спит и запись идёт, сборщик снимает экраны каждую минуту, даже если ввода нет. Если ввода с клавиатуры и мыши не было 5 минут и дольше, это пауза, и считается она с первой минуты: пометку «нет ввода» получают все минуты с последнего ввода. LLM описывает такую минуту по снимку: на экране созвон (Zoom, Meet, huddle в Slack) — «рабочее», явно личный звонок — «нерабочее», иначе — «ничего не делал», даже если на снимке ещё видна работа. Созвон без окна на экранах (свёрнут, идёт с телефона) распознать нельзя: он станет паузой. Без ввода меньше 5 минут (читаешь документ) минуты остаются обычными, дольше — весь отрезок становится паузой.

Чтобы пометка была верной с первой минуты, минута ждёт описания, пока не ясно, пауза это или нет. При работе — до следующего снимка: описание появляется на минуту позже. Без ввода минуты ждут до 5 минут. `report` и `summarize` без дня не ждут: последние минуты дня они описывают как обычные. Если пауза началась до полуночи, а 5 минут набралось после, минуты до полуночи остаются обычными.

Минуты пауз описываются LLM и стоят денег, как и остальные. Пока Mac спит или запись выключена, минуты не пишутся: в журнале это пропуск «не за компьютером» (от 5 минут), в отчёте — интервал «не за компьютером» (от 10 минут). Время за компьютером включает паузы, поэтому дни до этого изменения с новыми напрямую не сравнить.

### Причины пауз

Пауза — непрерывный отрезок дня из минут «нет ввода» и минут, за которые записей нет: Mac спал или запись была выключена. Отрезок совсем без минут «нет ввода» считается паузой, если он не короче 5 минут. Отлучка, за время которой Mac засыпал и просыпался, остаётся одной паузой. Созвон без ввода паузой не считается: отрезок, где не меньше половины описанных минут размечены как «рабочее» или «нерабочее», в паузы не попадает.

Когда ты возвращаешься к компьютеру после паузы, приложение за несколько секунд показывает поверх остальных окон небольшое окно «Зачем отходил?». В нём время паузы, занятие перед ней, поле для причины и до 6 недавних причин за последние две недели. Окно не забирает ввод с клавиатуры: чтобы написать причину, по нему нужно кликнуть. Enter или «Сохранить» записывает причину, клик по недавней причине записывает её сразу.

«Позже», Esc и закрытие окна прячут вопрос на 10 минут или до конца следующей паузы. Пауза при этом остаётся без причины. Окно спрашивает о таких паузах по одной, начиная с последней, а их число показано на значке приложения в Dock. Вопрос касается только сегодняшнего дня. Причину паузы любого дня можно записать в списке пауз в главном окне.

Вопрос появляется, только пока приложение запущено; главное окно при этом может быть закрыто. Если сборщик работает из терминала, а приложение не открыто, паузы копятся без причин и видны в списке, когда приложение откроют. Пока минуты отрезка без ввода не описаны, приложение не знает, пауза это или созвон, и может спросить о созвоне. Когда минуты описаны как созвон, отрезок сам пропадает из пауз.

## Данные

Каталог данных — `$DAYLOG_DIR`, по умолчанию `~/.local/share/daylog`. По каталогу на день `ГГГГ-ММ-ДД/`:

- `captures.jsonl` — записанные минуты: `{"t": "09:28", "app": "Warp", "frames": [...], "idle_sec": 12}`. `idle_sec` — сколько секунд на момент снимка не было ввода; при 300 и больше в строке есть ещё `"idle": true`. Первые минуты паузы в файле не помечены: они определяются по `idle_sec` следующих строк. В старых строках `idle_sec` нет;
- `minutes.jsonl` — описанные минуты: `{"t": "09:28", "app": "Warp", "activity": "…", "category": "work"}` (в старых строках `category` нет).;
- `report.md` и `report.json` — таймлайн дня крупными блоками (`report.json` читает приложение). У интервала «не за компьютером» в `report.json` категории нет;
- `pauses.jsonl` — причины пауз: `{"start": "14:22", "end": "14:30", "reason": "поговорил с Игорем", "at": "2026-11-16T14:30:41"}`. `start` и `end` — отрезок дня, конец не включён; `at` — когда причина записана. Строки только дописываются. Файла нет, пока не записана ни одна причина;
- `frames/` — кадры до описания (потом удаляются), `summarize.log`.

В корне каталога данных: `collector.lock` (PID сборщика), `collector.log` (вывод сборщика, запущенного из приложения) и необязательный `work.md` (что считать работой).

## Приложение

Запуск в режиме разработки:

```sh
cd app
pnpm install
pnpm tauri dev
```

Сборка:

```sh
cd app
pnpm tauri build
```

Готовое приложение — `app/src-tauri/target/release/bundle/macos/daylog.app`; его можно перенести в `/Applications`. Путь к `daylog.py` зашит при сборке: после переноса репозитория приложение нужно пересобрать или задать `DAYLOG_SCRIPT`.

Что умеет:

- список дней с рабочим временем и временем за компьютером, полоса дня с цветом по категории, итоги дня по категориям (клик — фильтр журнала);
- две вкладки дня: «Минуты» — поминутный журнал с поиском, открыт при запуске; «Таймлайн» — крупные блоки из `report.json`. Выбранная вкладка сохраняется при переходе к другому дню. Есть ли у дня отчёт, видно по кнопке «Собрать отчёт» / «Пересобрать отчёт» и вкладке «Таймлайн»;
- день с неразмеченными минутами размечается сам при открытии;
- список пауз дня под итогами: время, длительность и причина, то есть зачем отходил. Пауза без причины выделена. Причину можно записать в поле и сохранить клавишей Enter, а записанную — исправить, нажав на неё. Клик по времени паузы показывает её в журнале;
- окно «Зачем отходил?» при возвращении после паузы и число пауз без причины на значке в Dock, подробнее в разделе «Причины пауз»;
- «Собрать отчёт» / «Пересобрать отчёт» запускает `daylog.py report <день>`;
- «Начать запись» / «Остановить» запускает и останавливает `daylog.py run` (вывод — в `collector.log`). Сборщик, запущенный из терминала, приложение тоже видит и может остановить;
- закрытие окна запись не останавливает: окно возвращается кликом по иконке в Dock. Выход из приложения (Cmd+Q) останавливает сборщик, запущенный приложением; при следующем запуске запись возобновится сама, если её не остановили кнопкой.

Файлы дней приложение само не меняет: их пишет только `daylog.py`. Причины пауз тоже записывает он: приложение запускает `daylog.py pause`.

### Разрешение на запись экрана

macOS выдаёт разрешение Screen Recording приложению, от имени которого запущен сборщик. При запуске из терминала это терминал, при запуске из daylog.app — само приложение.

1. Остановите сборщик во вкладке терминала (Ctrl+C), если он запущен.
2. Откройте daylog.app и нажмите «Начать запись». Система покажет запрос, а приложение — полосу «Нужно разрешение на запись экрана».
3. Кнопкой «Открыть настройки» перейдите в System Settings → Privacy & Security → Screen & System Audio Recording и включите daylog.
4. Перезапустите daylog: разрешение действует после перезапуска, запись начнётся сама.

В режиме `pnpm tauri dev` приложение запущено из терминала, и разрешение берётся у терминала. Собранное локально приложение подписано ad-hoc: после пересборки macOS может попросить выдать разрешение заново.

## Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `DAYLOG_DIR` | каталог данных (по умолчанию `~/.local/share/daylog`) |
| `DAYLOG_MODEL` | модель для `claude -p` |
| `DAYLOG_KEEP_FRAMES` | `1` — не удалять кадры после описания |
| `DAYLOG_PYTHON` | `python3` для приложения; иначе первый найденный из `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` |
| `DAYLOG_SCRIPT` | путь к `daylog.py` для приложения; иначе путь, зашитый при сборке |

Приложению, запущенному из Finder, переменные терминала не видны. Передать их можно через `open`:

```sh
open --env DAYLOG_DIR=/tmp/daylog-copy app/src-tauri/target/release/bundle/macos/daylog.app
```
