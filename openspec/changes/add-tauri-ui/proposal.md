# Proposal

## Why

Сейчас день в daylog можно посмотреть только через `daylog.py report` в терминале или открыв `minutes.jsonl` руками. Нельзя быстро пролистать прошлые дни, найти минуту по слову и увидеть, сколько времени ушло на работу. Сборщик приходится держать в отдельной вкладке терминала.

Разбивка по приложениям на этот вопрос не отвечает: час в Warp может быть и работой, и разговором не о работе. Нужно видеть, сколько времени было рабочим, сколько нерабочим и сколько ушло впустую.

## What Changes

- Новое десктопное приложение на Tauri 2 в `app/`: окно со списком дней, полосой дня, таймлайном интервалов, поминутным журналом с поиском и итогами дня по категориям.
- `daylog.py summarize` размечает каждую минуту категорией «рабочее», «нерабочее» или «ничего не делал» тем же вызовом LLM, что и описание. «Ничего не делал» — только при явном простое; при сомнении минута считается занятием. Что считать работой, можно описать в `work.md` в каталоге данных.
- Новая команда `daylog.py classify <день>` доразмечает уже описанные минуты по тексту описаний. Приложение запускает её само при открытии дня с неразмеченными минутами, `daylog.py report` — перед сборкой; интервалы отчёта получают категорию.
- Полоса дня, журнал, таймлайн и итоги дня показывают категории; разбивки по приложениям нет.
- Кнопка запуска и остановки записи: приложение само стартует и завершает сборщик `daylog.py run`, вкладка терминала больше не нужна. Запись продолжается при закрытом окне и возобновляется при следующем запуске приложения.
- Файлы данных приложение само не пишет: читает их и обновляет открытый день по мере появления новых минут.
- Кнопка «Собрать отчёт» запускает существующий `daylog.py report <день>` и показывает результат.
- `daylog.py report` дополнительно сохраняет `report.json` с интервалами (рядом с `report.md`), чтобы приложению не разбирать markdown.
- `daylog.py run` держит блокировку на `collector.lock` в каталоге данных: по ней приложение знает, идёт ли запись, и второй сборщик не стартует поверх первого. Запуск `run` из терминала продолжает работать.

Вне рамок: иконка в строке меню, запуск приложения при входе в систему, показ скриншотов, правка записей, настройки модели.

## Capabilities

### New Capabilities

- `day-viewer`: просмотр дней daylog в окне приложения: список дней, полоса дня, таймлайн, поминутный журнал, поиск, время по категориям и рабочее время, обновление открытого дня.
- `report-generation`: сборка таймлайна дня через LLM: запуск из приложения, формат `report.json` с категориями интервалов, признак устаревшего отчёта.
- `activity-classification`: категория каждой минуты («рабочее», «нерабочее», «ничего не делал»), описание работы в `work.md`, доразметка уже описанных минут.
- `collector-control`: запуск и остановка сборщика из приложения, один сборщик на каталог данных, запись при закрытом окне, возобновление при запуске.

### Modified Capabilities

Нет: спецификаций в `openspec/specs/` ещё нет.

## Impact

- `daylog.py`: запись `report.json` в `cmd_report`, lock-файл в `cmd_run`, категория в `summarize`, новая команда `classify`. Формат `captures.jsonl` и `report.md` не меняется. В `minutes.jsonl` и интервалах `report.json` добавляется поле `category`; старые строки без него остаются валидными. `classify` перезаписывает `minutes.jsonl` дня, добавляя категории.
- Доразметка — один текстовый вызов LLM на день, при первом открытии старого дня; число вызовов при описании минут не меняется.
- Новый каталог `app/` (Tauri 2, Rust + React/TypeScript/Vite, pnpm). Зависимости только внутри `app/`; `daylog.py` остаётся на стандартной библиотеке.
- Разрешение Screen Recording нужно будет выдать самому приложению (сейчас оно выдано терминалу).
- Сборка отчёта из приложения тратит деньги на LLM так же, как `daylog.py report` из терминала.
