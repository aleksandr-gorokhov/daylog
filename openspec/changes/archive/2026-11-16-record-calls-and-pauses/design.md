# Design

## Context

Мотивация в proposal.md, требования в specs/. Что есть сейчас:

- `cmd_run` на каждой границе минуты читает `HIDIdleTime` из `ioreg`. Если ввода не было дольше `IDLE_SEC = 180`, минута пропускается через `continue`: в `captures.jsonl` ничего не пишется.
- `summarize` описывает ожидающие минуты пачками по `CHUNK = 5` одним вызовом LLM, передавая для каждой строку «время | активное приложение | файлы».
- Правила категорий (`CATEGORY_RULES`) говорят, что неизменный экран — не простой. Без дополнительного признака LLM разметит отошедшего человека по тому, что осталось на экране.
- 16 ноября во время созвона в Zoom с 12:33 по 12:51 активным приложением был Arc, но LLM по скриншотам описал эти минуты как созвон в Zoom. Скриншотов для распознавания звонка хватает.

## Goals / Non-Goals

**Goals:**

- Пока сборщик работает и Mac не спит, у каждой минуты есть строка в `captures.jsonl`.
- Минимум изменений: только `daylog.py`, приложение и формат `minutes.jsonl` не меняются.

**Non-Goals:**

- Определение созвона по микрофону или процессам: отказались ради простоты.
- Дешёвая запись паузы без LLM: без снимка нельзя отличить паузу от созвона.

## Decisions

### Не пропускать минуту, а помечать

`cmd_run` больше не делает `continue` при простое. Он снимает экран как обычно и, если простой ввода `>= IDLE_SEC` (300 с), добавляет в строку `"idle": true`. Альтернативы — писать паузу без снимка или ловить созвон по занятому микрофону — сложнее. Вдобавок первая не отличает созвон от ухода, а вторая требует CoreAudio через `ctypes`.

### Пометка доходит до LLM в строке минуты

`cmd_summarize` для минуты с `idle` дописывает в её строку промпта «нет ввода с клавиатуры и мыши 5 минут и дольше». В `CATEGORY_RULES` добавляется правило: при такой пометке минута — idle, если на снимке не идёт созвон. Если созвон идёт — work, а при явно личном звонке — nonwork. В `DESCRIBE_SYSTEM` добавляется указание: у такой минуты описывать паузу («отошёл, на экране …») или созвон («слушал созвон в Zoom …»). Правила категорий используются и в `classify`, но там пометки нет. Правило о ней там просто не срабатывает.

### Приложение и отчёт без изменений

Минута с пометкой — обычная строка `captures.jsonl` с кадрами. После описания она — обычная строка `minutes.jsonl` с категорией. Приложение уже показывает категорию idle на полосе, в журнале и в итогах. Отчёт уже склеивает минуты одной категории в интервалы, а «не за компьютером» ставит только на пропущенные минуты.

## Risks / Trade-offs

- [Минуты пауз описываются LLM, это стоит денег] → 30 минут паузы — 6 вызовов. Экран гаснет через 30 минут без ввода: тогда `screencapture` либо падает (минута не пишется), либо снимает чёрный экран (минута размечается как idle). Длинные отлучки дальше не тратят много.
- [Созвон без окна на экранах (окно свёрнуто, звонок с телефона) станет паузой] → осознанное ограничение. Микрофон можно добавить отдельным изменением, если это будет мешать.
- [Первые 5 минут паузы описываются по экрану] → небольшой перекос в пользу занятия. Это цена порога: короткое чтение не должно становиться простоем.
- [Видео без ввода станет паузой] → вне рамок.
- [Смысл «времени за компьютером» меняется для новых дней] → старые и новые дни нельзя сравнивать напрямую. Отмечается в README.

## Migration Plan

Миграция данных не нужна: поле `idle` необязательное, старые дни читаются как раньше. Сборщик подхватывает изменения после перезапуска записи («Остановить» → «Начать запись»). Приложение пересобирать не нужно. Откат: вернуть код. Старый код просто не смотрит на поле `idle`.
