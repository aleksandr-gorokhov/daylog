# Spec Delta

## MODIFIED Requirements

### Requirement: Список дней

Приложение SHALL показывать все дни, для которых в каталоге данных есть каталог с именем вида `YYYY-MM-DD`, от новых к старым, с временем за компьютером и рабочим временем. Признак собранного отчёта в списке дней MUST NOT показываться. Каталог данных SHALL браться из `DAYLOG_DIR`, а без неё — `~/.local/share/daylog`.

#### Scenario: Запуск приложения

- **WHEN** пользователь открывает приложение и за сегодня есть записи
- **THEN** в списке дней сверху стоит сегодняшний день, и он открыт

#### Scenario: Сегодня записей нет

- **WHEN** пользователь открывает приложение и каталога за сегодня нет
- **THEN** открыт самый поздний день из имеющихся

#### Scenario: Данных нет совсем

- **WHEN** каталог данных пуст или не существует
- **THEN** приложение показывает пустое состояние с подсказкой нажать кнопку запуска записи и не падает

#### Scenario: Посторонние каталоги

- **WHEN** в каталоге данных есть файл или каталог с именем не вида `YYYY-MM-DD`
- **THEN** он не попадает в список дней

#### Scenario: День с собранным отчётом

- **WHEN** у дня есть `report.json`
- **THEN** строка дня в списке выглядит так же, как у дня без отчёта: дата, рабочее время и время за компьютером, без метки отчёта

## ADDED Requirements

### Requirement: Вкладки дня

Приложение SHALL показывать открытый день на двух вкладках в таком порядке: «Минуты» (поминутный журнал) и «Таймлайн» (интервалы отчёта). При запуске приложения SHALL быть открыта вкладка «Минуты». Вкладка, выбранная пользователем, SHALL сохраняться при переходе к другому дню.

#### Scenario: Запуск приложения

- **WHEN** пользователь открывает приложение
- **THEN** открыта вкладка «Минуты», и она стоит первой

#### Scenario: Переход к другому дню

- **WHEN** пользователь выбрал вкладку «Таймлайн» и открыл другой день
- **THEN** у другого дня открыта вкладка «Таймлайн»
